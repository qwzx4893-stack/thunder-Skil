# A production brief that can be checked

Load when converting research or a broad request into a page/flow specification. Use the user's content and product model.

## Compact structure

Task/audience and observable success.
Scope: deliverable, existing system/stack, devices, language, non-goals.
Evidence: content/assets, reference principles, unknowns.
Direction: composition, type/color roles, media relation, optional key mechanism.
Behavior: entry -> action -> outcome; relevant states and recovery.
Acceptance: observable tasks, responsive views, accessibility, performance context.

Select page functions around the visitor's decision, not a compulsory template or section count.

| Function | Useful content | Failure |
|---|---|---|
| Opening | Subject, meaningful claim/experience, next step | Slogan with no product |
| Demonstration | Input, mechanism, output, limits | Invented screenshot presented as real |
| Proof | Attributable evidence or work | Fabricated endorsement/statistic |
| Comparison/specs | Aligned terms, units, differences | Chart contradicting accessible data |
| Pricing/action | Costs, commitment, what happens next | Misleading trial or competing main actions |
| Error/empty | What happened and how to proceed | Lost input or dead end |

Draft authorized copy, label demo facts, omit unsupported claims. A reference supplies craft, not product truth. Use product-ui.md for operational surfaces.

## Copy has the same anti-template duty

Name objects and actions in the end user's vocabulary rather than exposing internal architecture or the maker's design rationale. Prefer concrete verbs and consistent action names: a button and its outcome should describe the same action. Match brand and audience without filler, ornamental slogans, or forced cleverness. Use sentence case where the language supports it. Error/empty copy should explain the state and a useful next action; a vague apology or mood-setting sentence does not help recovery. Before keeping a label or sentence, identify what it helps the visitor understand or do.

## Example: oral-history archive

Visitors find recordings by place/date and understand provenance. Use supplied recordings, transcripts, permissions, and dates; missing portraits are optional. Organize an index with clear place/date hierarchy. Filter -> record -> play/read -> return retaining filters. Include no results, unavailable audio, loading, and keyboard operation. Acceptance: the task works narrow/wide, provenance is truthful, controls and focus work without decoration. Do not invent testimonials or pricing.

## Example: material-led product

Visitors compare construction and request a sample. Use actual material photos and dimensions. A static split crop or interactive reveal supports comparison. Both alternatives remain understandable without pointer motion; inquiry produces a clear result; mobile preserves the argument. Missing real media is an explicit asset issue.
